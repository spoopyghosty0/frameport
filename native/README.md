# Native components

FrameBridge includes automatic metadata retirement for the verified Meta XR Audio
Wwise build; see [AUDIO_METADATA.md](../docs/AUDIO_METADATA.md) for its lifetime
invariant and regression coverage. It uses the existing adapter installation.

`adapter/swapchain_pool.c` implements default-off GLES `swapchain_pool` (#387): at eight live app runtime
swapchains, eligible single-layer colour images use private GL textures packed into up to two lazy 4096² sRGB
runtime atlases. EndFrame copies each referenced source once and rewrites the final quads (including cylinder
strips), cylinders and stereo projection views after existing layer fixes. OpenXR image ownership, GL bindings,
scissor state, source fences, rectangle reuse and session cleanup are covered by `tests/test_swapchain_pool.py`
(`FRAMEPORT_NATIVE_TESTS=1`, host compiler + cached OpenXR and GLES/EGL/Vulkan headers). Host-tested;
4XVR submenu interaction, visual correctness and copy cost still need a headset check.
Vulkan sessions (#424, AC Nexus) use the same setting: format-43 (sRGB RGBA8) single-layer colour panels get private
device-local VkImages (app usage + transfer src/dst, returned as `XrSwapchainImageVulkanKHR`), moved to
COLOR_ATTACHMENT_OPTIMAL at their first acquire; xrEndFrame records one command buffer per frame (a 3-deep fence ring
on the binding's queue, submits under `flip_lock`) with vkCmdCopyImage into the waited atlas image (COLOR_ATTACHMENT ->
TRANSFER_DST -> COLOR_ATTACHMENT) before releasing it. Quads flagged VERTICAL_FLIP (`flip_emul`, also without the
pool) use the same atlases: a pooled panel's copy becomes a vkCmdBlitImage with reversed rows, a runtime swapchain's
quad gets a per-frame atlas area with an upside-down blit of its shown image; the app's images are only read. Other formats and every arraySize-2 (eye) image keep runtime swapchains. The harness
checks layouts, copy regions, the ring and AC Nexus' swapchain count with a recording Vulkan double; the real queue,
layouts on Turnip and the picture need the device.

Sources of the prebuilt binaries in `../artifacts/` (committed, with `SHA256SUMS`). End users never compile anything;
developers rebuild with `python native/build.py` (downloads NDK r27c, OpenXR headers at pinned commits, d8 into
`native/.cache/`, git-ignored). The adapter, GL shim and platform compat rebuild byte-identically; the VrApi bridge
embeds debug paths (`-g`) and the dex depends on the d8 version, so those differ in bytes only.

The ovr_* stub library is *not* prebuilt: `src/frameport/analysis/stubgen.py` generates it per game from the exact
missing symbols (no compiler needed).

After changing anything here: `python native/build.py`, commit artifacts + SHA256SUMS, then run `frameport parity`
(the report marks updated binaries as "expected") and a device launch test.

`adapter.fixed_resolution` (off by default, #406/#394) keeps META recommended layer
resolution at tracked full swapchain size. Both adapter GIPA and xrshim's existing
extension entry point serve it; the setting adds OVRPlugin shim routing. The extension
stays visible, avoiding dependence on a plugin fallback. No adapter revision bump for
this opt-in fix. See DEVICE_NOTES "Fixed layer resolution / Batman" for verification.

FrameBridge fixes of November 2026 (no adapter revision bump: all are read from settings.conf at start or are
on by default in every build): `perf_settings.c` answers `xrPerfSettingsSetPerformanceLevelEXT` with XR_SUCCESS
when the runtime lacks it (`perf_settings_emul`, default on, #336/#400); `swapchain_formats.h` lists GL_RGBA8 /
Vulkan UNORM after the runtime's sRGB formats (`unorm_formats`, opt-in, #400); `eye_pose_fix.c` + `eye_pose.h`
give each projection view its eye's offset when a game submits one pose twice (`eye_pose_fix`, opt-in, #527);
`detached_controllers.c` also leaves detached-controller entries out of xrSyncActions' active sets (wrapping
whichever xrSyncActions hook comes next, #476); `haptic_log.c` + `haptic_summary.h` log a per-hand haptics
summary every 10 s while vibrations happen (logging only, #567); `wait_balance.c` closes a waited frame nobody
begins within 100 ms before the next xrWaitFrame, which SteamVR would block forever (`wait_balance`, default on,
#135). Header parts are host-tested by
`tests/test_framebridge_round2.py` (the OpenXR ones with `FRAMEPORT_NATIVE_TESTS=1`).
